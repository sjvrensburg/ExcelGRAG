# Codebase audit — 2026-08-31

A six-way parallel audit of every crate (correctness, missed bugs, UX), with the
top findings spot-verified against the code. Baseline at audit time: `cargo
clippy --workspace --all-targets` clean, `cargo test --workspace --release`
~400 tests green, 1 ignored.

This document is written as a work order: each issue carries the location, the
mechanism, a concrete failure, a proposed fix, and how to verify the fix. Line
numbers are as of commit `0196d6a`; re-locate by the quoted code if they have
drifted.

**Ground rules for whoever implements these** (from CLAUDE.md — read it first):

- Any change touching `eg-ingest` or the XLSB path must be cross-checked
  against sheet-oracle (`eg-ingest --example dump_cells` vs the SheetJS dump)
  before committing.
- `eg check` currently agrees on 100% of what it can evaluate. Any fix to
  `eg-eval` must keep it that way — run it against a real workbook before and
  after. Several fixes below *remove* false `Differs` verdicts; none may add
  one.
- Never put anything derived from `private/` (sheet names, values, labels)
  into git or this repo's docs.
- `cargo test -p eg-retrieve --test answers` asserts the unanswered set
  exactly; retrieval changes that fix or break an answer must update it.
- Fixes should come with tests shaped to catch the regression, in the crate's
  existing test files.

Severity: **C** = breaks a bolded invariant or leaks confidential data.
**H** = wrong answers or broken deployments in realistic use. **M** = wrong or
degraded behavior in narrower conditions, or a measured-performance
regression. **L** = UX/polish.

## C1. Whole-column and whole-row references are invisible to the formula scanner

- **Where:** `crates/eg-model/src/formula.rs:63` (`scan_references`),
  `crates/eg-model/src/address.rs:386` (`parse_local_parts` requires both
  letters and digits).
- **Confidence:** high — verified by executing a compiled probe against
  eg-model.

**Problem.** `SUM(A:A)`, `SUM(Sheet1!B:B)`, `SUM(3:3)`, `SUM('Q3 Sales'!C:C)`
all produce **zero** references. Every `A:A`-style reference yields no graph
edge. `audit()` cannot catch the omission because it re-derives edges with the
same scanner — this is the shared-implementation blind spot the audit's own
docs warn about. Compounding it, `scan_names` then emits the endpoints as
candidate defined names (`SUM(A:A)` → names `["A", "A"]`); if the workbook
defines a name `A` (legal in Excel for any single letter except `C`/`R`), the
graph gets a *wrong* `REFERENCES_NAME` edge instead of a missing one. The
README states the reference workbook's aggregation sheets read whole columns,
so this hits the primary workload, not a corner.

**Fix.** Teach the reference scanner to recognise `COL:COL` and `ROW:ROW`
forms (with optional `$` and optional sheet prefix). Suggested representation:
extend `RangeRef` (or add a variant) for open-ended ranges — whole-column
(`col_start..=col_end`, rows unbounded) and whole-row — rather than faking a
huge concrete range, so downstream layers can decide how to clamp. Then:

1. `eg-graph` lifting: clamp the open range to the sheet's used extent when
   finding overlapping regions (regions are finite, so the existing
   one-edge-per-touched-region logic applies once clamped).
2. `eg-graph/src/audit.rs` `resolve` must mirror the same clamping exactly —
   build and audit must stay a mirrored pair.
3. `scan_names` must stop emitting the endpoints of a column/row range as name
   candidates.
4. `eg-eval` already refuses to *evaluate* `A:A` deliberately; keep that, but
   confirm the refusal is by shape (`Unsupported::…`), not a scan miss.

**Verify.** New unit tests in `eg-model` for each form (relative/absolute,
sheet-qualified, quoted sheet). A graph-level test: a workbook fixture with
`=SUM(A:A)` must produce an edge to the region(s) the column intersects, and
`cargo test -p eg-graph --test audit` extended with a broken-clamp case. Run
the lifting audit (`eg index`) against a real corpus.

## C2. What-if's downstream closure is blind to defined names

- **Where:** `crates/eg-eval/src/whatif.rs:522` (`readers_of`),
  `crates/eg-eval/src/whatif.rs:485` (`blocking_input`).
- **Confidence:** high — spot-verified: both walk formulas with
  `scan_references_into`, which sees A1-style references only, while
  `calc.rs:770` evaluates defined names.

**Problem.** A formula that reads the changed cell *through a defined name* is
never found by the closure walk: not moved, not blocked, simply omitted.
Scenario: name `Tax_Rate` refers to `RATES!B4`; `=Tax_Rate*A1` is filled down
hundreds of thousands of cells; `what_if(RATES!B4=0.15)` reports every one of
them unaffected, with no banner. This violates the bolded invariant "a what-if
never reports a cell it could not evaluate as unchanged" in spirit — impact is
silently understated, the precise failure the Blocked machinery exists to
prevent. `blocking_input` has the same blindness, so a cell reading a blocked
cell via a name can be reported `Moved` from a stale stored input.

**Fix.** Before the walk, resolve the workbook's defined names once into a map
`name → resolved CellRef/RangeRef` (the workbook model already carries the
definitions; `calc.rs` already has resolution logic — reuse it, do not fork
it). In `readers_of`/`blocking_input`, when scanning a formula, additionally
scan its name tokens (`scan_names` exists) and translate each matched name to
its target range before the frontier-intersection test. Names defined as
formulas/constants rather than references should make the reading cell
**Blocked** (refused), not silently skipped — refusal over guessing.

**Verify.** New tests in `crates/eg-eval/tests/whatif.rs`: (a) a cell reading
the override via a name is reported `Moved`; (b) a cell reading a *blocked*
cell via a name is `Blocked`, not `Moved`; (c) a name defined as `=A1+1`
(non-reference) blocks its readers.

## C3. Zero-argument unmodelled functions answer `#VALUE!` instead of being refused by name

- **Where:** `crates/eg-eval/src/calc.rs:1260` (`Eval::call`, the
  `args.is_empty()` guard). Spot-verified.
- **Confidence:** high.

**Problem.** The guard

```rust
if args.is_empty() && !matches!(name, "TRUE" | "FALSE" | "NA") && !VOLATILE.contains(&name) {
    return Ok(err(ErrorKind::Value));
}
```

fires before the unsupported-function fallthrough, so any legitimately
zero-argument function that isn't modelled — `PI()`, `ROW()`, `COLUMN()`,
`SHEET()` — computes `#VALUE!` rather than returning
`Unsupported::Function(name)`. Against a stored value (e.g. `=PI()` caches
3.14159…) that is `Outcome::Differs`: a guessed wrong verdict, breaking both
the "unsupported functions are refused by name, not guessed" invariant and the
"any new disagreement is a regression" property of `eg check`. `ROW()`/
`COLUMN()` with no arguments are common in real workbooks.

**Fix.** Invert the order: check "is this function modelled at all?" first;
only apply the too-few-arguments → `#VALUE!` rule to functions the evaluator
knows (where the minimum arity is known). Everything unmodelled falls through
to `Unsupported::Function(name)` regardless of arity. Note `ROW()`/`COLUMN()`
are arguably *positional* rather than volatile — refusing them by name is
correct today; do not implement them as part of this fix.

**Verify.** Tests in `crates/eg-eval/tests/calc.rs`: `=PI()` and `=ROW()` →
`Unsupported::Function`, and `=EXACT("a")` (modelled, too few args) still →
`#VALUE!`. Then run `eg check` on a real workbook: the unsupported count may
rise; the disagree count must not.

## C4. The `profiles/` confidentiality lifecycle leaks stored cell values

Two related defects, found independently by two auditors. `profiles/` is the
one corpus directory that holds real cell values (distinct values, sums,
minima) — CLAUDE.md's bolded confidentiality warning is about exactly this.

### C4a. `Corpus::forget` leaves the profiles file on disk and keeps serving it

- **Where:** `crates/eg-graph/src/store.rs:340` (`forget`),
  `crates/eg-graph/src/store.rs:388` (`profiles`). Spot-verified: `forget`
  removes the manifest entry and `graphs/<hash>.json` only.
- **Confidence:** high.

**Problem.** After `forget(hash)`, `profiles/<hash>.json` remains on disk
forever; worse, `Corpus::profiles()` reads the file directly without
consulting the manifest, so a "forgotten" workbook's cell values are still
served to any caller holding the hash.

**Fix.** In `forget`, after removing the graph file, also remove the profiles
file (same NotFound-tolerant pattern; keep the documented manifest-first
ordering). In `profiles()`, consult the manifest before reading — a hash
absent from the manifest returns a miss. While there: `profiles()` performs no
`content_hash` verification the way `get` does; add the same check so a
filename-prefix collision cannot serve the wrong workbook's values
(`store.rs:438` names files by a 32-char prefix; `get` guards, `profiles()`
does not).

### C4b. Re-indexing with `--no-profiles` does not remove previously stored values

- **Where:** `crates/eg-cli/src/corpus.rs:104` (indexing path never calls
  `forget_profiles`), `crates/eg-graph/src/store.rs:293` (`put` carries stale
  `profiled_columns`/`profile_values` manifest flags forward).
- **Confidence:** high.

**Problem.** Index a confidential workbook with profiles; realize the mistake;
re-run `eg index corpus/ book.xlsb --no-profiles`. The old value-bearing
`profiles/<hash>.json` survives, the manifest still advertises it, the tool
exits 0 with no warning. CLAUDE.md promises "`--no-profiles` for none at all".
(`--redact-values` is fine — it overwrites the file.)

**Fix.** Make absence authoritative on re-index: when the CLI indexes a
workbook without producing profiles, call `Corpus::forget_profiles(hash)`
(it exists, is currently never called) and clear the manifest flags — either
in the CLI path or, better, inside `Corpus::put` semantics: `put` without an
accompanying `put_profiles` for the same hash in the same indexing pass should
drop stale profile state rather than carry it forward. Choose one place;
document the contract on `put`.

**Verify (both).** Tests in `crates/eg-graph/tests/store.rs`: after `forget`,
the profiles path does not exist and `profiles()` misses; after a
`put`-without-profiles over a hash that had them, the file is gone and the
manifest flags cleared. A CLI-level check that a `--no-profiles` re-index
leaves no `profiles/<hash>.json`.

## H1. Cycles spanning walk levels are iterated, not reported

- **Where:** `crates/eg-eval/src/whatif.rs:563` (`order_within`).
- **Confidence:** high.

**Problem.** Cycle detection only sees edges *within one level* of the walk. A
cycle whose members sit at different shortest distances from the change —
change `A1`; `B1=A1+C1`, `C1=B1` — ping-pongs between levels for all
`max_levels`, reporting both cells `Moved` with last-visit values and
`Stopped::Levels`, never `Blocked::Cycle`. Violates "a cycle is reported
rather than iterated to a fixed point". The existing test
(`a_cycle_is_reported_rather_than_iterated`) only covers the same-level case.

**Fix.** Detect cycles across the whole walk, not per level. Cheapest sound
approach: track, per cell, how many times it has been re-judged; a cell
revisited more than once whose value has not stabilised (or simpler: any cell
visited a third time) is in or downstream of a cycle — mark the strongly
connected set `Blocked::Cycle` and propagate no-answer to its readers, per the
invariant. Alternatively build the reader graph over the closure once and run
SCC (the closure is bounded; `readers_of` already computes the edges) —
sounder, and reuses `order_within`'s existing edge logic.

**Verify.** Extend `tests/whatif.rs` with the cross-level cycle above:
expected `Blocked::Cycle` for both cells, no `Moved`, no `Stopped::Levels`.

## H2. Path-qualified external-workbook references misparse as bogus 3-D references

- **Where:** `crates/eg-model/src/address.rs:352-381` (`parse_sheet_prefix`).
- **Confidence:** high — verified by execution.

**Problem.** `'C:\Reports\[Book1.xlsx]Sheet1'!A1` — the form Excel stores when
a linked workbook is closed — parses to `sheet_name: Some("C")`,
`end_sheet_name: Some("\Reports\[Book1.xlsx]Sheet1")`, `workbook: None`. After
unquoting, the code only looks for a *leading* `[`; a full path starts with a
drive letter, and the string is then split on the drive's `:` as if it were a
3-D range. The graph lifts this to a nonexistent sheet "C" instead of an
external-workbook node.

**Fix.** In `parse_sheet_prefix`, after unquoting, search for a `[`…`]` pair
anywhere in the prefix (not just position 0): text before `[` is the
directory path, the bracketed part the workbook, text after `]` the sheet.
Only treat `:` as a 3-D separator when no bracket pair is present. Keep the
existing leading-`[` fast path. Also handle the POSIX-path form (`'/data/[Book1.xlsx]Sheet1'!A1`).

**Verify.** Unit tests for the quoted-path form (Windows drive path, POSIX
path, path containing `:` after the drive), asserting `workbook` is populated,
`end_sheet_name` is `None`, and the sheet name is right. Confirm existing 3-D
tests still pass.

## H3. Lexical search errors are swallowed and reported as "NOTHING MATCHED"

- **Where:** `crates/eg-retrieve/src/search.rs:302, 321, 325, 403` — every
  lexical search error goes through `unwrap_or_default()`. Spot-verified.
  `SearchError::Query` (`search.rs:25`) is defined for exactly this and never
  constructed.
- **Confidence:** high.

**Problem.** A corrupted/unreadable tantivy segment (disk error, permissions,
concurrent writer) yields `Err`, treated as zero hits → `Verdict::Nothing` →
the `NOTHING MATCHED.` banner. The user or agent concludes the corpus doesn't
contain the answer when the search never ran — the evidence layer, built so
retrieval fails loudly, failing silently.

**Fix.** Propagate: replace the four `unwrap_or_default()` sites with `?`
mapped into `SearchError::Query` (it exists). `find`/`find_in` already return
`Result`; the CLI and MCP surfaces already render errors properly (MCP as
`isError` results). The per-word coverage probe at `:403` may arguably degrade
gracefully instead — if so, record that the probe failed and say so in the
evidence line rather than reporting words unmatched.

**Verify.** A test that opens a corpus, corrupts/removes a segment file, and
asserts `find` returns `Err`, not an empty `Search`.

## H4. MCP JSON-RPC layer loses the request id on invalid requests (client hangs)

- **Where:** `crates/eg-mcp/src/lib.rs:34-40` + `crates/eg-mcp/src/rpc.rs`.
  Spot-verified: a serde failure on `Request` → `Response::anonymous_err(PARSE_ERROR, …)` with `id: null`.
- **Confidence:** high.

**Problem.** `{"jsonrpc":"2.0","id":7,"method":123}` (or any object missing
`method`) is syntactically valid JSON but fails `Request` deserialization; the
server answers `id:null`, code -32700. Per JSON-RPC 2.0 this must be -32600
Invalid Request carrying `"id":7`. Every correlating MCP client fails to match
the reply and times out on that call.

**Fix.** Two-stage decode: parse the line as `serde_json::Value` first; if
that fails → -32700 with `id:null` (correct). Otherwise pull `id` out of the
object, then deserialize into `Request`; on failure → -32600 with the
extracted id.

**Related (fix together).** `crates/eg-mcp/src/server.rs:63-70`: `initialize`
echoes back *any* lexicographically smaller `protocolVersion` string,
including revisions the server does not implement (`"1.0"`, or
`"2025-03-26"`, whose batching this transport rejects with an anonymous
-32700). Compare against an explicit whitelist of supported revisions; on an
unknown/newer version, answer with the latest supported one (per MCP spec).

**Verify.** Unit tests on the dispatch loop: valid-JSON/invalid-request →
-32600 with original id; unparseable line → -32700 id null; notification
(no id) with bad shape → no response. An `initialize` test asserting only
whitelisted versions are echoed.

## H5. Relative workbook paths stored verbatim break every cell-level MCP tool

- **Where:** `crates/eg-cli/src/corpus.rs:103-112` (path stored as typed at
  index time), `crates/eg-mcp/src/state.rs:118-125` (opened as stored at serve
  time).
- **Confidence:** high.

**Problem.** `eg index corpus/ book.xlsb` stores the relative path. An MCP
client launches the server with its own cwd (the documented deployment in
`eg-mcp/main.rs`), so `read_cells` etc. fail with "the corpus indexed
book.xlsb, and there is no file there now. The graph remembers where a
workbook was, not where it went." — actively misleading; the file never moved.

**Fix.** Canonicalize (`fs::canonicalize`) the workbook path at `put` time in
the CLI indexing path, storing an absolute path. For existing corpora, add a
fallback at open: if the stored path is relative and missing, try resolving it
against the corpus directory's parent and against the cwd, and if found,
say which resolution worked. Update the error message to distinguish "stored
relative path, server running elsewhere" from "file actually gone", and to
suggest re-indexing.

**Verify.** Test: index with a relative path, chdir elsewhere (or resolve the
manifest entry directly), assert the stored path is absolute and the workbook
opens.

## H6. Empty-but-present optional arguments treated as omitted; Excel treats them as 0/FALSE

- **Where:** `crates/eg-eval/src/calc.rs:1668` (VLOOKUP), `:1746` (MATCH),
  `:1807` (same pattern); mirrored in `crates/eg-eval/src/schema.rs:328` and
  `:383`.
- **Confidence:** medium-high.

**Problem.** In Excel, `=VLOOKUP(x,tbl,2,)` — trailing comma, empty fourth
argument — passes 0/FALSE: an **exact** lookup. Here
`Some(Literal(Empty)) | None => true` makes it approximate. With a missing
key, Excel gives `#N/A`; this evaluator returns the last value ≤ key — a
wrong *number*, not just a wrong verdict. Same at `MATCH(k,r,)` (Excel exact
mode 0, here mode 1). In `schema.rs`, the same formulas are either dropped
from schema inference (`:328`) or classified `approximate: true` (`:383`) — a
declared foreign key misfiled as a banding.

**Fix.** Distinguish `None` (argument omitted → default TRUE/1) from
`Some(Literal(Empty))` (written empty slot → coerce Empty like 0/FALSE →
exact). Audit the same `Some(Empty) | None` pattern across all optional-arg
functions in `calc.rs` — the ones where Excel's omitted-vs-empty semantics
differ. Apply the matching change to `schema.rs` classification.

**Verify.** `tests/calc.rs`: `=VLOOKUP("z",tbl,2,)` with "z" absent → `#N/A`;
`=MATCH(k,r,)` behaves as mode 0. Schema test: `VLOOKUP(...,)` infers an
exact key. Then run `eg check` on a real workbook — disagreements must not
increase (they may decrease).

## H7. A schema change silently wipes the lexical index during a read-only `ask`

- **Where:** `crates/eg-index/src/text.rs:246-262` (`TextIndex::open`
  deletes and rebuilds on schema mismatch).
- **Confidence:** high on mechanism.

**Problem.** Upgrade `eg` across a tokenizer/schema change and run `eg ask`
(not `eg index`): `open` wipes `corpus/text` and rebuilds it *empty*. Every
subsequent ask is semantic-only, and `term_hits` finds all content words
"unmatched", so the BLIND banner asserts words indexed yesterday appear
nowhere in the corpus — false. Nothing suggests reindexing; results silently
degrade until the user happens to rerun `eg index`. A destructive rebuild
triggered by a read-only verb is also surprising in itself.

**Fix.** Split the API: a read-only `open` that, on schema mismatch, returns a
typed `StaleSchema` error (never deletes); a `open_or_reset` used only by the
indexing path. On the ask path, surface `StaleSchema` as a clear message:
"the index format changed with this version of eg — run `eg index <corpus>`
to rebuild." Do the equivalent review of `VectorIndex::open`.

**Verify.** Test: build an index, alter the stored schema marker, `open` →
`StaleSchema` and the directory untouched; `open_or_reset` rebuilds.

## M1. `Table::read` reintroduces the per-cell probe pattern the one-pass invariant forbids

- **Where:** `crates/eg-structure/src/table.rs:144-156`; consumed by
  `crates/eg-eval/src/query.rs:250` for every table query.
- **Confidence:** high on mechanism, medium on magnitude.

**Problem.** Each row of `Table::read`'s iterator does one
`sheet.get_ref((row, col))` — a `BTreeMap` point lookup, O(log n) — per
column, instead of one `iter_range` scan per row with gap-fill. On the
reference-scale region (a hundred-plus columns by a hundred thousand rows) that is tens of millions of point lookups
into a multi-million-entry map. This is the access pattern that measured 3.5x
slower when `read_table` did it; `read_table`/`profile_table` themselves
comply, but the row iterator they hand out does not.

**Fix.** Rewrite the row iterator to call `sheet.iter_range` (or `iter_row`)
once per row and gap-fill against the expected column positions while walking
the returned run — the same technique `read_table` already uses. No API change
needed; `Row` construction stays the same.

**Verify.** Existing table/query tests stay green. Add a timing sanity check
as an example, not a test; or simply confirm with `eg-eval`'s query example
against a large sheet.

## M2. `dominant_kind`'s sample cap counts populated cells, degenerating on sparse tall regions

- **Where:** `crates/eg-structure/src/region.rs:510-542`; called per candidate
  header row by `count_header_rows` and again by `has_row_labels`.
- **Confidence:** high that the scan happens; medium on real impact.

**Problem.** Regions are bounding boxes; density < 1 is normal. A column with
50 populated cells in a very tall region scans the full height (BTreeMap
lookups) before collecting its 64-cell sample, and does so up to 4× (3
candidate header rows + row-labels check): ~460k lookups for one mostly-empty
column, multiplied across sparse columns.

**Fix.** Bound by *rows scanned*, not populated cells found: break after
`k × SAMPLE` rows (k=4 is fine) whatever was collected. The sample is a
heuristic input; a bounded sample is as good.

**Verify.** Existing region tests green; add one asserting `dominant_kind` on
a sparse column returns without visiting more than the bound (or just rely on
the behavior tests, since this is a perf fix with unchanged semantics for
dense columns).

## M3. 3-D references lifted to the start sheet only, invisibly

- **Where:** `crates/eg-graph/src/build.rs:374` (ignores `end_sheet_name`);
  `crates/eg-graph/src/audit.rs:311` identically blind, so audit passes.
- **Confidence:** high on code path; medium on real-workbook impact.

**Problem.** `=SUM(Jan:Dec!B2)` produces a dependency edge to Jan only;
Feb–Dec regions get no edge, no dangling record, no report counter, and
`audit()` returns `agrees()`. eg-model parses `end_sheet_name`; eg-eval
refuses it by name; eg-graph silently drops the decision.

**Fix.** Minimum: count dropped 3-D spans in `BuildReport` so the omission is
visible (mirror the counter in the audit so they stay a pair). Full fix:
enumerate the sheets between start and end (workbook sheet order is known) and
lift the reference against each — then update `audit.rs::resolve` to do the
identical enumeration. Do both sides in one commit; a one-sided change turns
the audit into a false alarm.

**Verify.** Extend `eg-graph` build+audit tests with a 3-D fixture: either
the counter increments (minimum) or one edge per spanned sheet exists and the
audit agrees (full).

## M4. Formula text bypasses `--redact-values`

- **Where:** `crates/eg-mcp/src/tools.rs:489, 588, 724` (`read_cells`,
  `recompute` result.formula, `what_if` replaced/moved formula,
  `precedents`/`dependents` reference text); CLI equivalents
  `crates/eg-cli/src/workbook.rs:200, 311`.
- **Confidence:** high on behavior; medium on whether it violates intent.

**Problem.** Under `--redact-values`, a cell holding
`=IF(A2="Smith, John",B2*0.15,0)` prints its formula in full — literals
(names, rates) leave the machine while the value column shows `<number>`. The
flag's help says "contents should not leave the machine"; neither it nor
CLAUDE.md states the labels-vs-values line. `tables` similarly prints titles
and headers unredacted.

**Fix.** Decide the line explicitly, then implement one of: (a) redact string
and numeric literals inside formula text when redacting (replace with
`<text>`/`<number>` while keeping structure and references — a small pass over
the formula string using the existing scanner's literal-skipping logic); or
(b) document that formulas and headers are structure, not values, in the flag
help and CLAUDE.md. Option (a) matches the flag's promise; if (b) is chosen it
must be written down. **This is a judgment call for the maintainer — ask
before implementing (a) vs (b).**

**Verify.** For (a): a redaction test through `read_cells` and `recompute`
asserting no literal survives.

## M5. MCP `context` tool cannot be scoped to a workbook or sheet

- **Where:** `crates/eg-mcp/src/tools.rs:72-87, 368-375`.
- **Confidence:** high.

**Problem.** `search` takes `workbook`/`sheet` filters; `context` — "usually
the right first call" — declares neither, and `additionalProperties: false`
rejects them. In a multi-workbook corpus an agent naturally passes the same
filter it just used with `search`, gets a schema rejection, and without it the
passage mixes workbooks.

**Fix.** Add the same optional `workbook`/`sheet` parameters to `context`'s
schema and thread them through to `find_in` (the plumbing exists for
`search`). Keep the two schemas' descriptions consistent.

**Verify.** MCP-level test calling `context` with a workbook filter; assert
scoped results.

## M6. `expand()` drains its budget LIFO, inverting seed priority for context

- **Where:** `crates/eg-retrieve/src/expand.rs:398-407, 414` (`pending` is a
  Vec popped from the back).
- **Confidence:** high on mechanism; medium on practical impact (default
  budget 40 usually absorbs it).

**Problem.** Seeds are pushed in rank order, then popped LIFO, so the
*worst*-ranked seed's ancestry (region/sheet/workbook) and children consume
remaining budget before the best seed's. With 5 seeds and budget 8, the top
hit renders with no `in:` path while the fifth is fully named — inverting the
documented "a budget that runs out never costs a better-ranked hit for a
worse one" for the context that makes hits citable.

**Fix.** Use a FIFO (`VecDeque`) for the drain, or drain each seed's ancestry
in seed-rank order before descending. Preserve the property the auditor
verified: all distance-n steps pop before distance-n+1 (FIFO keeps it).

**Verify.** Test in `tests/expand.rs`: small budget, multiple seeds, assert
the top seed's ancestry is present and the last seed's is the one cut.

## M7. `find()` loads the embedding model even when it won't be used

- **Where:** `crates/eg-retrieve/src/search.rs:277`.
- **Confidence:** high.

**Problem.** `embedder(dir)` runs before `fusion.lexical_only` (or "does this
corpus have vectors at all") is consulted: `--lexical-only` still pays the
ONNX load and, on a fresh machine, attempts the ~130 MB download — the exact
costs the flag exists to avoid.

**Fix.** Hoist the `lexical_only` / no-vectors check above `embedder(dir)`;
construct the embedder lazily only on the semantic path.

**Verify.** Test or manual check: `--lexical-only` against a corpus with no
model cache and `EG_MODEL_CACHE` pointed at an empty dir must succeed without
network.

## M8. Headerless declared Excel tables gain a phantom header row

- **Where:** `crates/eg-ingest/src/lib.rs:406-414`
  (`has_header_row = !columns.is_empty()`).
- **Confidence:** medium.

**Problem.** `<tableColumn>` elements exist even when `headerRowCount="0"`
(Excel auto-names them Column1…), and calamine only shifts `dims.start` when
the header count ≠ 0. A table created with "My table has headers" unchecked
gets `top = body_top - 1`: the stored range annexes whatever row sits above
the table and calls it a header — in the layer CLAUDE.md calls ground truth.

**Fix.** Derive `has_header_row` from the table's `headerRowCount` attribute
(exposed by calamine / the fork), not from the presence of columns. If
calamine doesn't expose it, that is a fork patch + `docs/upstream-issues.md`
entry. Remember the reader rule: diff against sheet-oracle before committing.

**Verify.** Fixture with a headerless table (authored in real Excel, per the
fixtures convention) exercised through `tests/parity.rs` as both xlsx and
xlsb; assert the range and `has_header_row: false`.

## M9. Declared totals rows are dropped end-to-end (and the fork miscomputes them)

- **Where:** `crates/eg-ingest/src/lib.rs:420` (hard-codes
  `has_totals_row: false`); `crates/eg-structure/src/region.rs:171-183`
  (`Region` has no totals concept, so `body()` would sweep a declared totals
  row into data); calamine fork `src/xlsx/mod.rs:689-691` (subtracts
  `header_row_count` instead of `totals_row_count` from `dims.end` when
  `totalsRowCount != 0` — coincidentally right for 1-header/1-totals, wrong
  for headerless-with-totals).
- **Confidence:** high that the field is dropped; medium on present impact
  (latent while ingest hard-codes false).

**Problem.** A workbook that *declares* its totals row still gets the
"totals row swept into a body doubles every sum" failure the invariants warn
about — the one case where the ground truth was available.

**Fix.** Three coordinated pieces: (1) fix the fork's subtraction and add the
defect to `docs/upstream-issues.md` (it is fork defect number eight); (2)
plumb `has_totals_row` through ingest from the table XML; (3) give `Region` a
totals concept for *declared* tables only (e.g. `totals_rows: u32`,
nonzero only when declared) and make `body()` exclude it — detection-based
regions stay as they are, no new guessing.

**Verify.** Parity fixture with a declared totals row; assert `body()`
excludes it and `profile_table` sums only the body. sheet-oracle diff for the
fork change.

## M10. Arithmetic overflow escapes as `Number(inf)`; text "inf"/"nan" coerces

- **Where:** `crates/eg-eval/src/calc.rs:1101-1105` (only `^`, `EXP`, `PV` go
  through `number_or_num_error`), `:1009-1023` (`to_number` uses Rust
  `f64::from_str`, which accepts `"inf"`, `"infinity"`, `"nan"`).
- **Confidence:** high on mechanism; medium on frequency.

**Problem.** `=1E308*10` → Excel `#NUM!`, here `Number(inf)` → false
`Differs`, contradicting the file's own "Excel has no infinity" rule. A cell
holding text `"inf"` makes `=A1+1` compute infinity where Excel gives
`#VALUE!`; a NaN then poisons `same()`/`compare`.

**Fix.** Route all four basic operators' results through
`number_or_num_error` (non-finite → `#NUM!`). In `to_number`, reject
non-finite parses and the `inf`/`nan` spellings (parse, then
`is_finite()` check → `#VALUE!` for text coercion).

**Verify.** `tests/calc.rs`: `=1E308*10` → `#NUM!`; text `"inf"` operand →
`#VALUE!`. Run `eg check` — no new disagreements.

## M11. A reverted revisit leaves stale downstream verdicts in what-if

- **Where:** `crates/eg-eval/src/whatif.rs:353-361`.
- **Confidence:** medium (constructed scenario; mechanism plain).

**Problem.** A revisited cell that recomputes back to its stored value
(`Agrees`) becomes `Unchanged` and its override reverts — but it is not added
to `moved_here`, so downstream cells that consumed its *intermediate* moved
value are never re-judged: they stay listed `Moved` with an `after` computed
from a value that no longer stands.

**Fix.** Treat a revert as a move for propagation purposes: insert the cell
into `moved_here` (its value changed from the overlay's previous state), so
its readers are re-judged next level; they will then also revert if
appropriate. This composes with the H1 cycle fix — a revert-loop must
terminate via the cycle detection, not iterate.

**Verify.** `tests/whatif.rs` with the auditor's construction: change A;
`D=-A`, `E=D`, `B=A+E` (stored value equals recomputed), `C=B+1`; assert C
ends `Unchanged`.

## M12. Top-level multi-cell range converts refusal into `#VALUE!`

- **Where:** `crates/eg-eval/src/calc.rs:701` (`result`'s `Err(_) =>` arm).
- **Confidence:** medium-high.

**Problem.** `=A1:C1` at the top of a formula (spill in 365, implicit
intersection in legacy — either way a real stored value) is answered
`#VALUE!` instead of `Unsupported::RangeAsValue`, which `deref` correctly
returns everywhere else → false `Differs`.

**Fix.** In `result()`, propagate the `Unsupported` from `deref` instead of
mapping it to `#VALUE!`.

**Verify.** `tests/calc.rs`: `=A1:C1` → `Unsupported::RangeAsValue`, not a
computed error.

## M13. Stopword-only or empty queries produce hits plus a garbled BLIND banner

- **Where:** `crates/eg-retrieve/src/search.rs:178-186, 237-247`.
- **Confidence:** high.

**Problem.** For `eg ask corpus show me all` every word is in `FRAME`, so
matched/unmatched/covered are all empty — but `VectorIndex::search` is
thresholdless top-k and always returns hits. `verdict()` hits
`covered.is_empty()` → `Blind`, and `warning()`'s `matched.is_empty()` arm
renders "BLIND MATCH: none of  appears anywhere in this corpus" — malformed
(empty list) and false. The true situation — "the question carried no content
words" — has no arm.

**Fix.** Add an explicit case: when the extracted term set is empty, short-
circuit with a distinct verdict/message ("every word in the question is a
frame word — ask with the terms you want found") and consider skipping
retrieval entirely rather than returning semantically-arbitrary hits.

**Verify.** Unit test on `warning()`/`verdict()` with an all-stopword query;
assert the new message and no empty-list interpolation.

## Low / UX (grouped by surface)

### CLI

- **L1. `eg check` exits 0 on disagreement** (`eg-cli`). CLAUDE.md calls any

  *Fix:* nonzero exit (suggest 2) when disagreements > 0; document in help.
- **L2. A typo'd corpus path is silently materialized** —
  `eg-graph/src/store.rs:204-208` `create_dir_all`s unconditionally, and
  `TextIndex::open`/`VectorIndex::open` do the same, so `eg ask corups/ q`
  creates a skeleton corpus and prints NOTHING MATCHED, exit 0. *Fix:*
  read-only verbs (`ask`, `search`, `workbooks`, `serve`) refuse a directory
  with no `manifest.json` ("no corpus at <path> — did you mean … / run `eg
  index` first"); only `index` creates.
- **L3. `TooLarge` speaks Rust API jargon** — `eg-ingest/src/lib.rs:53-57`

- **L4. The Blind banner names MCP tools to CLI users** —
  `eg-retrieve/src/search.rs:240-252` says "Verify with `read_cells`"; the CLI

  neutral wording: "read the cells it names").
- **L5. Multi-workbook `eg index` failure leaves earlier workbooks stored but
  unindexed** — `eg-cli/src/corpus.rs:30-39,170-234`; a bare re-run heals it

  that rerunning `eg index <corpus>` completes the indexes; consider indexing
  after each put instead of batching.
- **L6. Filter-flag asymmetry** — CLI `search` takes `--sheet` but no
  workbook filter; `ask` takes neither; MCP `search` takes both. *Fix:* offer

  `eg-cli/src/workbook.rs:222-224`; a quoted sheet name containing `=` cannot

### eg-model / eg-eval minutiae

- **L17. `parse.rs:368` slices at a byte offset** —
  `rest[..literal.len()]` panics on a multibyte char straddling the boundary

  `rest.as_bytes().get(..len)` or `starts_with`.
- **L18. Approximate VLOOKUP/MATCH return the first duplicate key; Excel's

  continue past equal keys to the last match. (Empirical Excel behavior;
  verify against a fixture before relying on it.)
- **L19. Exact text lookups ignore `*`/`?` wildcards** — Excel honours them

- **L20. `COUNTBLANK` disagrees with the crate's own `is_empty()`** —

- **L21. `''!A1` parses as unqualified** — `address.rs:373` swallows an empty

### Known verification gaps (document, don't necessarily fix)

- **V1.** `check`/`audit` pin only *summed* `REFERENCES_NAME` and
  `CROSS_WORKBOOK_REF` weights (`eg-graph/src/check.rs:186`, audit module

## What was checked and found sound

So a fixing agent doesn't re-litigate these: RRF fusion arithmetic (weighted,
0-based-rank equivalent to the published form) and the case/digit-boundary
tokenizer including multibyte offsets; `expand`'s nearest-first-then-heaviest
ordering and true shortest-distance `hops`; `render` carrying no cell values,
no dangling citations; every search surface routing through
`find`/`find_in`; the build/audit mirror on every constructed divergence
(hint state, straddling ranges, self-loops, case-insensitive sheets); region
boundary arithmetic, never-overlap, strict-majority column typing; profile
sums excluding error cells; formula grouping's merge rules; `query`'s
ambiguity/non-numeric refusals and raw-accumulate-round-once with `over`
ranges; the overlay's by-column no-scan contract and `Evaluator`
invalidation; MCP's isError-vs-protocol-error line and newline framing;
redaction of proper cell values on every printing path; profile values never
entering the text or vector indexes; A1 parsing of quoted sheets with
embedded `!`/doubled quotes, unterminated-quote defenses, no reachable panics
from malformed addresses.
